## 처리 규칙

파싱은 형식대로 원문을 나누고, 정규화는 같은 의미의 컬럼·행위를 공통 이름으로 맞춘다. UTC 기준으로 이벤트 시각을 통일하며 적재 시각은 별개로 보관한다. 원문은 `rawEvent`, 사용하지 않는 필드는 `unmapped`에 남긴다. 공개 버전의 원문은 이미 별칭으로 치환된 입력이며 기업 제공 원본이 아니다.

| 판단 | 이유 |
|---|---|
| 문자열 공백 분리 대신 로그 형식별 파싱 | User-Agent·명령행·XML·JSON에 공백과 중첩 구조가 있음 |
| Linux 계정과 콘솔 계정을 분리 | 이름이 같다는 이유만으로 동일인을 확정할 수 없음 |
| Sysmon `src`를 서버 IP로 해석 | 접속자 IP와 의미가 다름. 공통 타임라인에서 `dvc`로 이동 |
| 엔티티 연결 근거 보존 | 로그의 직접 관측과 IP·시간에 의한 추정을 구분 |

- [파싱 예: nginx](../scripts/01_parse_nginx.py), [Sysmon](../scripts/01_parse_sysmon.py)

- [행위 분류 검증](../scripts/99_verify_event_action.py): 공통 행위 규칙.
- [통합 검증](../scripts/99_verify_integrated.py): 행 수·시각·연결 사례.
- [전체 검증](../scripts/verify_portfolio.py): 9,125개 이벤트 키, 146개 세션 키 및 참조 무결성.

공개 버전에서 행 수와 관계를 유지하도록 비식별 처리했다. 사설 IP는 데모용 사설 대역으로, 실제 공인 IP는 문서용 주소로 바꿨다. 따라서 네트워크 분류의 설명 근거가 일부 달라질 수 있으며 주소의 실제 위치·고객·원래 계정으로 해석하지 않는다.
